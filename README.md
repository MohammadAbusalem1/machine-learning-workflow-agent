# Machine Learning Workflow Agent

An LLM-driven Python agent that orchestrates reproducible machine-learning workflows using deterministic tools for dataset loading, preprocessing, model training, evaluation, and visualization.

The project supports natural-language requests such as:

```text
Train a logistic regression model on the Iris dataset, evaluate it, and visualize the results.
```

The language model chooses the next tool to call, while scikit-learn performs the actual machine-learning operations and metric calculations.

## Why This Project

The project demonstrates how an LLM can act as a controller around conventional ML code rather than replacing the underlying algorithms. The agent can translate a user request into a sequence of dataset, preprocessing, training, evaluation, and visualization operations.

## Supported Workflows

### Datasets

- Iris
- Palmer Penguins

### Models

- Logistic Regression (`solver="lbfgs"`)
- Decision Tree (`max_depth=3`)
- K-Nearest Neighbors (`n_neighbors=5`)

### Tools

- `model_memory`
- `dataset_loader`
- `dataset_preprocessing`
- `train_model`
- `evaluate_model`
- `visualize_results`

## Architecture

```text
Natural-language request
          |
          v
      LLM agent
          |
          v
   JSON tool action
          |
          v
+-------------------------+
| Deterministic ML tools  |
| - load dataset          |
| - preprocess            |
| - train model           |
| - evaluate              |
| - visualize             |
+-------------------------+
          |
          v
   Tool observation
          |
          +------> back to agent
```

The LLM never invents evaluation metrics. Accuracy, precision, recall, F1 score, confusion matrices, and plots are generated by the Python ML pipeline.

## Portfolio Refactor

This repository is based on a two-person university course assignment and has been refactored for portfolio use. The portfolio version:

- removes student/course submission material;
- removes hard-coded API credentials;
- separates agent logic from ML tools;
- corrects the Penguins workflow to use **species** as the classification target;
- normalizes model and dataset aliases so agent tool calls are less brittle;
- fits feature scaling only on the training set;
- uses a structured JSON action protocol instead of free-form action parsing;
- adds reusable visualizations and basic automated tests.

The original coursework was collaborative; this repository should not be interpreted as claiming sole authorship of the original team submission.

## Setup

Create and activate a Python virtual environment, then install the dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows PowerShell, activate with:

```powershell
.venv\Scripts\Activate.ps1
```

## API Configuration

Copy the example environment file:

```bash
cp .env.example .env
```

Then add your own Groq API key to `.env`:

```text
GROQ_API_KEY=your_api_key_here
```

Never commit `.env` or a real API key.

The model can also be changed without editing source code:

```text
GROQ_MODEL=llama-3.3-70b-versatile
```

## Run the Agent

From the repository root:

```bash
python -m src.main "Train a logistic regression model on the Iris dataset, evaluate it, and visualize the results."
```

Another example:

```bash
python -m src.main "Train a decision tree on the Penguins dataset and evaluate it."
```

Generated plots are written to the `artifacts/` directory, which is ignored by Git by default.

## Run Tests

```bash
pytest -q
```

The tests verify the deterministic Iris workflow and model-name alias handling without requiring an LLM API call.
