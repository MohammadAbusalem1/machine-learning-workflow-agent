# Machine Learning Workflow Agent

An LLM-driven Python agent that orchestrates reproducible machine-learning workflows using deterministic tools for dataset loading, preprocessing, model training, evaluation, and visualization.

The project supports natural-language requests such as:

```text
Train a logistic regression model on the Iris dataset, evaluate it, and visualize the results.
```

The language model chooses the next tool to call, while scikit-learn performs the actual machine-learning operations and metric calculations.

## Why This Project

This project demonstrates how a large language model can act as a controller around conventional machine-learning code rather than replacing the underlying algorithms.

The agent translates a user request into a sequence of operations such as:

1. Select and load a dataset
2. Preprocess the data
3. Train a machine-learning model
4. Evaluate model performance
5. Generate visualizations
6. Return the results to the user

The LLM controls the workflow, while deterministic Python tools perform the actual data processing, training, evaluation, and plotting.

- `visualize_results`

## Architecture

```text
Natural-language request
          |
          v
      LLM agent
          |
          v
   JSON tool action
          |
          v
+-------------------------+
| Deterministic ML tools  |
|                         |
| - load dataset          |
| - preprocess data       |
| - train model           |
| - evaluate model        |
| - visualize results     |
+-------------------------+
          |
          v
   Tool observation
          |
          +------> back to agent
```

The LLM does not generate evaluation metrics itself.

Accuracy, precision, recall, F1 score, confusion matrices, and plots are generated by the underlying Python machine-learning pipeline.

## Machine-Learning Pipeline

The deterministic workflow handles:

- Dataset loading
- Missing-value handling
- Feature and target separation
- Categorical feature encoding
- Train/test splitting
- Feature scaling
- Model training
- Prediction
- Classification metrics
- Confusion-matrix generation

Feature scaling is fitted only on the training data to avoid information leakage from the test set.

## Portfolio Refactor

This repository is based on a two-person university machine-learning course project and was reorganized and refactored for portfolio use.

The portfolio version:

- removes student and course submission information;
- removes hard-coded API credentials;
- separates agent logic from machine-learning tools;
- uses environment variables for API-key management;
- corrects the Penguins workflow to use species as the classification target;
- normalizes dataset and model aliases;
- fits preprocessing operations using the training data where appropriate;
- uses structured JSON actions for tool calls;
- separates the code into reusable Python modules;
- adds automated tests;
- adds technical documentation;
- adds reusable visualization support.

The original coursework was collaborative, so this repository does not claim sole authorship of the original team submission.

## Setup

### 1. Clone the Repository

```bash
git clone https://github.com/MohammadAbusalem1/machine-learning-workflow-agent.git
cd machine-learning-workflow-agent
```

### 2. Create a Virtual Environment

On macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

On Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Install Dependencies

```bash
pip install -r requirements.txt
```

## API Configuration

The deterministic machine-learning tools and automated tests can run without an LLM API key.

To run the complete LLM-driven agent, copy the example environment file:

```bash
cp .env.example .env
```

Then add your own Groq API key to `.env`:

```text
GROQ_API_KEY=your_api_key_here
```

The model can optionally be configured through the same file:

```text
GROQ_MODEL=llama-3.3-70b-versatile
```

Never commit a real API key or `.env` file to GitHub.

## Run the Agent

From the repository root:

```bash
python3 -m src.main
```

The default workflow requests a Logistic Regression model on the Iris dataset.

You can also provide your own request:

```bash
python3 -m src.main "Train a logistic regression model on the Iris dataset, evaluate it, and visualize the results."
```

Another example:

```bash
python3 -m src.main "Train a decision tree on the Penguins dataset and evaluate it."
```

Generated visualizations are written to the:

```text
artifacts/
```

directory.

That directory is excluded from Git through `.gitignore`.

## Security

API credentials are never stored directly in the source code.

The repository includes:

```text
.env.example
```

as a configuration template, while the real:

```text
.env
```

file is excluded by `.gitignore`.

The following files and directories are also ignored:

```text
.env
.venv/
venv/
__pycache__/
.pytest_cache/
*.pyc
artifacts/
.DS_Store
```
